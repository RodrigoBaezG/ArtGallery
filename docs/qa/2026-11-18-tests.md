## 2. Cómo ejecutar

```bash
cd tests && npm install && npx playwright install chromium webkit
npm test                # unit + security + e2e (local); sigue aunque una fase falle y resume al final (helpers/run-all.mjs)
npm run test:unit       # node --test unit/*.test.mjs
npm run test:security   # node --test security/*.test.mjs + playwright --project=security-chromium
npm run test:e2e        # playwright --project=chromium --project=webkit
npm run test:prod       # contra https://kukobaezartgallery.netlify.app (o BASE_URL=…)
npx playwright show-report   # informe HTML de la última ejecución
```

Requisitos: `tools/images/node_modules` instalado para `npm run verify` (si falta, el test se
salta con aviso); red para Google Fonts y `npm audit`. `test:prod` con `NETLIFY_TOKEN` y
`NETLIFY_SITE_ID` comprueba además el honeypot contra la API de envíos de Netlify.

**`.gitignore`**: no lo toco (no es mío). He creado `tests/.gitignore` con `node_modules/`,
`test-results/`, `playwright-report/` y `blob-report/`. Si se prefiere en el raíz, añadir:
`/tests/node_modules`, `/tests/test-results`, `/tests/playwright-report`, `/tests/blob-report`.

## 4. Fallos reales

Severidad según §12.5: **Bloqueante** = cualquier fallo de unit, de seguridad, de axe
serious/critical, de consola o de scroll horizontal, o XSS. **Importante** = LCP ≥ 2,5 s,
cabeceras incompletas, `npm audit` moderate (y, por analogía, el peso de la home).
Las áreas táctiles no están en la lista de §12.5; las clasifico como Importante/Menor.

### B1 — Bloqueante (unit) · `Artworks.url(art)` no conserva `lang`
- **Archivo**: `frontend/assets/js/gallery.js` (`window.Artworks.url`).
- **Evidencia**: `unit/gallery.test.mjs` › «Artworks.url(art) conserva lang…»: con `index.html?lang=es`,
  `Artworks.url({id:'paco-disco'})` devuelve `work.html?id=paco-disco` (sin `lang`) y los enlaces de
  la galería y de anterior/siguiente pierden `?lang=es`.
- **Causa**: `url: function (art) { return 'work.html?id=' + encodeURIComponent(art.id); }`.
- **Impacto real**: bajo mientras `localStorage` funcione (el idioma persiste por ahí); con
  almacenamiento bloqueado (modo privado de algunos navegadores) el visitante vuelve a EN al abrir una obra.
- **Dueño**: `frontend-dev`.
- **Corrección**: añadir `&lang=` cuando la URL actual lleva `?lang` (o siempre con `I18n.lang`),
  igual que ya hace el canonical en `work.js`.

### B2 — Bloqueante (consola, WebKit) · `artworks.json` precargado y descargado dos veces
- **Archivos**: `frontend/index.html:37` y `frontend/work.html:37`:
  `<link rel="preload" href="data/artworks.json" as="fetch" crossorigin>`.
- **Evidencia**: `e2e/matrix.spec.mjs` › «consola limpia también 5 s después de cargar» (index y
  work-first, solo WebKit) y el recorrido de quien contrata a 1440 px en WebKit:
  `warning: The resource http://localhost:4173/data/artworks.json was preloaded using link preload but not
  used within a few seconds from the window's load event.` y `/data/artworks.json ×2` en red.
  Reproducible 3/3 en WebKit; Chromium lo reutiliza bien (1 petición, sin aviso).
- **Causa**: WebKit no casa el preload `as="fetch"` con el `fetch()` de `gallery.js`, así que lo
  descarga otra vez y avisa a los ~3 s (por eso la matriz, que termina antes, no lo veía).
- **Dueño**: `frontend-dev`.
- **Corrección**: quitar el preload (el JSON pesa ~4 KB; la ganancia es mínima) o comprobar en
  WebKit una combinación que sí reutilice la precarga. Volver a pasar el test de 5 s.

### B3 — Bloqueante (seguridad) · `sharp` con vulnerabilidad *high* en `tools/images`
- **Archivo**: `tools/images/package.json` (`"sharp": "^0.33.5"`) y su lockfile.
- **Evidencia**: `security/privacy.test.mjs` › `npm audit --omit=dev en tools/images`:
  `{"high":1}` — `sharp <=0.35.5-rc.1` (libvips/libheif/librsvg; GHSA-f88m-g3jw-g9cj, GHSA-rgj7-g3m4-5g8c, GHSA-wq5f-xc86-pv6w).
- **Impacto real**: bajo (herramienta local que solo procesa imágenes propias; no se despliega),
  pero §12.4 exige 0 high/critical.
- **Dueño**: `image-curator`.
- **Corrección**: subir a `sharp@^0.35.5` (cambio mayor), `npm install`, `npm run build --force`
  en una copia o sobre una obra para confirmar que la salida no cambia, y `npm run verify`.

### B4 — Bloqueante (seguridad) · posible credencial en el historial de git
- **Archivo**: historial, commit `6e0d167`, `backend/.env.example` (backend ya eliminado en `614fb80`).
- **Evidencia**: `security/privacy.test.mjs` › «escaneo de secretos en el historial»: patrón
  «URI de base de datos con credenciales» (`postgres://usuario:contraseña@…`) en una línea comentada

### I1 — Importante (rendimiento) · la home a 1440 px pesa 2,4 MB en la primera vista
- **Archivos**: `frontend/assets/js/gallery.js` (`sizes()`, `EAGER`) y, en segundo plano, el
  peso de los WebP (`tools/images`).
- **Evidencia**: `e2e/perf.spec.mjs` › «peso de la home… (1440px)»: **2437 KB** (imágenes 2320 KB)
  frente al límite de 1,5 MB. A 375 px: 551 KB (pasa). Diagnóstico a 1440 px: se descargan

- **Dueño**: `frontend-dev`.
- **Corrección sugerida**: ajustar `sizes` al ancho real de cada fila (sin el margen 1,4, o

  `content-visibility`/lazy por debajo del pliegue. Si no basta, `image-curator` puede revisar

## 5. Ajustes razonados a la especificación

| Punto de §12 | Ajuste | Motivo |
|---|---|---|
| `description` sin vacíos | Se exige coherencia EN/ES (ambas vacías o ambas con texto) y se avisa | Rodrigo no ha dado descripciones y §1.6 prohíbe inventarlas; `work.js` omite la vacía. |
| `status` ∈ enum, `year` entero | También se admite `[[TODO]]` (con aviso) | §12.2 permite TODO «listado como aviso»; es el marcador oficial de dato pendiente. |
| Notación `pagina.seccion.elemento` | ≥ 2 segmentos, camelCase, namespace conocido | `notFound.*` y `meta.siteName` no tienen sección; forzar 3 niveles sería ruido. |
| Un `<h1>` por página (estático) | `work.html` admite 0 en el HTML | Su `h1` lo pinta `work.js`; se comprueba en jsdom y en E2E (exactamente 1). |
| canonical/hreflang en los 6 HTML | `404.html` exento | Es `noindex`; canonical/hreflang serían contradictorios. |
| CSS sin valores sueltos | Lista blanca: `@media` (no admiten custom properties), `1px` de `.visually-hidden`, duraciones 0, custom properties locales que referencian tokens | Sin ella, solo falsos positivos. Resultado: 0 valores sueltos. |
| Áreas táctiles ≥ 44 px | Exentos: enlaces en línea dentro de una frase (excepción WCAG 2.5.8), skip link fuera de pantalla, honeypot | El resto se mide en ancho y alto (44×44). |
| Reduced motion «duración > 0» | Umbral 1 ms | El CSS usa la técnica estándar `0.01ms !important` (1e-05 s), que anula el movimiento. |
| Lazy: «como máximo las eager» | Nada fuera de eager + margen del navegador (2500 px) y las obras lejanas no se descargan | El lazy nativo precarga por diseño cerca de la ventana; no es controlable por el sitio. |
| CSP en local | Se aplican las cabeceras de `netlify.toml` interceptando las respuestas, **sin** `upgrade-insecure-requests` | Subiría `http://localhost` a https. Verificado que la CSP simulada bloquea un `style=""` inyectado. |
| Tab con foco visible | Omitido en WebKit | WebKit (como Safari por defecto) no enfoca enlaces con Tab. |
| `maxlength` «en todos los campos» | nombre, email y mensaje | El honeypot no lo necesita y el `select` no lo admite. |
| `npm audit --omit=dev` en `tests/` | Se audita todo | `tests/` solo tiene devDependencies; con `--omit=dev` no auditaría nada. |
| gitleaks | No instalado: escaneo propio con regex (AWS, GitHub, claves privadas, `password=`, URIs con credenciales, Slack, Google, Stripe, `api_key`) sobre `git ls-files` y `git log -p --all`, y búsqueda de `.env` en todo el historial | Equivalente práctico; si se instala gitleaks, puede sustituirlo. |
| Rendimiento | Solo Chromium (CDP); 4G = perfil «Slow 4G» de Lighthouse (150 ms, 1,6 Mbps) + CPU ×4 | WebKit no expone CDP. |
| Fotos para pintar / mockups | Solo `readdirSync` de nombres (55), comparados por nombre sin extensión con `source` de `artworks.json`, `manifest.json` y los archivos de `frontend/` | Sin leer contenido, como pide §6. 0 coincidencias. |
| «La respuesta de éxito no refleja datos» | Comprobado en local (jsdom y Playwright con `POST /` interceptado); en producción solo dentro del test de honeypot con token | Un envío real crearía una entrada en Netlify. |
